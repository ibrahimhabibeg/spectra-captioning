About the project: I am working on a project to align astronomical spectra with language. We will do training in LLaVA style. Thus, the first pahse (which is the one we are working on now) is to create captions that will be used to train the mapping module that aligns the representations from a spectra encoder with a language model. This is the only phase you will be working on.

What is being worked on in this repo:

This specific repo works on the spectra captioning. Particulary, there are two tasks that need to be performed in here: generating captions for the spectra by relying on matched papers that contains ground truth data and the creation of a GUI that allows domain experts to view the plot of the spectra, its metadata, and the captions generated by the LLM. There will be various captioning strategies so the GUI should allow the viewer to easily view the captions generated by the various strategies, compare between them, and share their thoughts.

I believe that these are two sepa,rate parts. That is the captions should be generated offline and stored in local files and the GUI should be an independent app that ingests the files generated by the captioning app and then do its work.

Your work will focus on the first part and you shall be responsible for the captioning.

All captions shall be generated using Gemini and the code shall rely on Google genai Python SDK. I haven't decided yet on the shape of the data that shall be generated by the captioning part so that will be your job. Keep in mind that I would appereciate the exsistance of as much information as possible. This includes the thought traces of the model, the stragey, number of used tokens, price, etc.

About the dataset: For the astronomical observations, I will rely on two datasets: SDSS and DESI. Both datasets are available in HATS format in the MMU collection on Hugging Face with the IDs `UniverseTBD/mmu_sdss_sdss` and `UniverseTBD/mmu_desi_edr_sv3`. For reference, I have stored the READMEs for both datasets in this workspace under the `hf_readme` folder.

For the papers information, I will rely on the on the `astronolan/galaxy-mentions-hats` dataset. You will also find its readme stored in `hf_readme`. Each row in this dataset contains a matching between a paper and an astronomical object and each row contains the quotes from the paper. This will be textual information acting as the source truth.

Note that you will have to match the spectra with the papers first. The readme contains clear instructions on how this can be perfomed with any generic MMU dataset in HATS format.

Now, regarding the captioning process, you have to know that I did try the captioning before and had catastrophically bad results due to the prompts used. You can find those prompts in the `old_prompts` directory. Note that this was a slightly different setting where I either used a full paper or used only its title and abstract instead of the matche precise quotes.

The problem faces was that the captions directly referenced the name of the objects and included information that was impossible to know from the spectra alone. Recall that the captions will be used to align the represetnation of the spectra encoder with the language encoder. Including information that isn't available in the spectra itself will teach the downstream model to hallucinate. I have kept the older results for 6 samples in the `old_results` directory for reference.

I have 3 captioning strageies in mind. 

1. Pass only the quotes from the papers to Gemini and ask it to generate a caption based on the quotes. The prompt should be absolutely clear that the captions should be based ONLY on information from the quotes and ONLY information that can be extracted from the spectra. The caption should NEVER mention the name of the object.
2. Pass the quotes from the papers and the spectra to Gemini and ask it to generate a caption based on the quotes and the spectra, but this time the prompt will instruct Gemini to only reference scientific information from "the following list". This can include elements like redshift and chemical composition.
3. Two stages. First extract the scientific information in a structured format from the quotes, and then use either a template or Gemini to generate the caption based on the structured information.

I think you start the work with the first stragey and keep in mind that other approaches will be added at a later time.

One more thing to keep in mind is that I won't be running the captioning process on the full dataset. I will just be creating a few (about 10) samples for now. It is abolutely necessary that the code allows this. At a later time, I will scale to larger size. First, I would probably only on about 100 observation and even later I could scale to the full dataset for which there are matches.
